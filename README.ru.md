[![CI](https://github.com/s11va9/network-manager-vless/actions/workflows/ci.yml/badge.svg)](https://github.com/s11va9/network-manager-vless/actions/workflows/ci.yml)

[![License: GPL-2.0-or-later](https://img.shields.io/badge/license-GPL--2.0--or--later-blue)](LICENSE)

Плагин VPN для [NetworkManager](https://networkmanager.dev/), добавляющий подключения
**VLESS** на базе [Xray-core](https://github.com/XTLS/Xray-core).

Серверы VLESS становятся обычными VPN-подключениями: они добавляются в Настройках
GNOME, включаются в шторке рядом с Wi-Fi и управляются через `nmcli`. Маршруты, DNS и
переподключение берёт на себя NetworkManager.

**[Скачать последнюю версию](../../releases/latest)** · [Установка](#установка) ·
[English version](README.md)

## Возможности

- **Интеграция с Настройками GNOME**: тип «VLESS (Xray)» в диалоге добавления VPN,
  редактор всех параметров и заполнение из ссылки `vless://`. Интерфейс на русском и
  английском.
- VLESS поверх TCP (с XTLS Vision), XHTTP, WebSocket, HTTPUpgrade и gRPC; TLS и REALITY.
- Полный туннель для IPv4 и IPv6 через TUN-устройство, DNS внутри туннеля без утечек
  через физическую сеть. Маршруты туннеля важнее маршрутов по умолчанию других
  VPN-клиентов, а локальный системный прокси другого клиента на время подключения
  выключается, поэтому браузеры, терминалы и остальные приложения идут через туннель.
- Автоматический перезапуск Xray-core, если он завершился во время подключения.
- Подписки с автообновлением, которое сохраняет ваши изменения в подключениях.
- **Один пакет**: Xray-core уже внутри, его контрольная сумма сверена с официальной.
- Разделение привилегий: xray работает от пользователя без прав. Учётные данные хранит
  NetworkManager, в логи они не попадают.

## Установка

Скачайте пакет для своей архитектуры из [последнего релиза](../../releases/latest)
(`amd64` — для большинства компьютеров, `arm64` — для ARM) и откройте его: в Ubuntu
двойной щелчок по `.deb` открывает Центр приложений. Или установите из терминала —
зависимости подтянутся сами:

```sh
sudo apt install ./network-manager-vless_0.5.0_amd64.deb
```

Всё: NetworkManager сразу видит плагин, перезагрузка и настройка не нужны.
Поддерживаются Ubuntu 24.04 и новее, а также другие дистрибутивы с NetworkManager 1.24+,
GTK 4.6+ и Python 3.11+.

Если во время установки или обновления были открыты Настройки GNOME, перезапустите их:
они держат ранее загруженный плагин в памяти (в том числе в фоне — для поиска в обзоре
«Действия»). Остановить их можно командой `pkill -x gnome-control-c`; при следующем
запуске загрузится новая версия.

Удаление: `sudo apt remove network-manager-vless`.

## Использование

### Настройки GNOME

1. Откройте **Настройки → Сеть**, нажмите **+** рядом с **VPN** и выберите **VLESS (Xray)**.
2. Вставьте ссылку `vless://` в поле **Импорт из ссылки** и нажмите **Заполнить** — или
   введите параметры вручную.
3. Задайте имя подключения и нажмите **Добавить**.

Подключение появится в списке VPN и в шторке. Кнопка ⚙ открывает тот же редактор.

**Подписки:** вставьте в то же поле адрес подписки `https://` и нажмите **Добавить
подписку**. Каждый сервер подписки станет отдельным VPN-подключением и будет
обновляться автоматически; диалог добавления VPN после этого можно закрыть.
Файл со ссылкой можно импортировать через **Импортировать из файла…** в диалоге
добавления VPN.

### Командная строка

```sh
nm-vless import -                    # вставьте ссылку: она не видна и не попадёт в историю
nmcli connection up "Мой сервер"
nmcli connection down "Мой сервер"
nm-vless list                        # подключения, * — активное
nm-vless export "Мой сервер"         # вывести ссылку vless://
nm-vless check                       # проверить установку
nm-vless test "Мой сервер"           # проверить, открываются ли сайты через него (без VPN)
```

### Подписки

```sh
nm-vless subscription add -          # вставьте https:// адрес подписки
nm-vless subscription list
nm-vless subscription update
nm-vless subscription remove ИМЯ     # удаляет и её подключения
```

Подписки обновляются автоматически с интервалом, который задаёт провайдер
(`profile-update-interval`, по умолчанию 6 часов); таймер проверяет это каждый час
(`systemctl --user list-timers nm-vless-subscriptions.timer`). Обновление добавляет новые
серверы, обновляет изменившиеся (UUID подключения и ваши настройки, например
автоподключение, сохраняются) и удаляет исчезнувшие. Активное подключение не удаляется
никогда, а ответ без единого рабочего сервера ничего не меняет. До 0.5.0 на Ubuntu каждое
обновление добавляло все серверы заново (netplan терял метку, связывающую профиль с
подпиской); первое обновление в 0.5.0 оставляет копию, которой вы пользовались
последней, и удаляет остальные. Если провайдер отдаёт
подписку только определённым клиентам, укажите `--user-agent`.

### Дополнительные параметры

MTU, DNS-серверы и маршрутизация IPv6 — в разделе **Дополнительно** редактора или так:

```sh
nmcli connection modify "Мой сервер" +vpn.data "mtu=1400, dns=9.9.9.9, ipv6=no"
```

Все ключи описаны в [docs/connection-settings.md](docs/connection-settings.md).

## Как это работает

Служба узнаёт IP сервера до создания туннеля и сообщает его NetworkManager как адрес
VPN-шлюза. NetworkManager прокладывает маршрут к этому адресу через физический
интерфейс, поэтому собственное соединение xray не зацикливается в туннель. Служба
(root) создаёт TUN-устройство и передаёт его xray, который работает от пользователя
`nm-vless` без каких-либо привилегий.

Кроме маршрута по умолчанию туннель получает `0.0.0.0/1` и `128.0.0.0/1` (для IPv6 —
`::/1` и `8000::/1`). Они точнее любого маршрута по умолчанию, поэтому трафик идёт
через VLESS, даже пока поднят туннель другого клиента. Чтобы направлять через VLESS
только его собственную сеть, включите «Использовать это подключение только для
ресурсов в его сети» на вкладках IPv4/IPv6 (`ipv4.never-default yes`).

`nm-vless-proxy-guard.service` работает в сеансе пользователя: пока VLESS подключён, а
системный прокси GNOME указывает на локальный прокси другого клиента (например,
`127.0.0.1:10809` у Happ), он выключает системный прокси, а после отключения VLESS
включает обратно. Отключить это поведение:
`systemctl --user disable --now nm-vless-proxy-guard.service`.
Подробнее: [docs/architecture.md](docs/architecture.md).

## Диагностика

```sh
nm-vless check
nm-vless test "Мой сервер" https://example.org/    # сайты через сервер, без подключения VPN
journalctl -b -t nm-vless-service                   # сообщения службы и xray
resolvectl status                                   # DNS по интерфейсам
ip route get 1.1.1.1                                # должен идти через vless*
```

### Часть сайтов открывается, остальные — «соединение закрыто»

Браузеры показывают `ERR_CONNECTION_CLOSED` (в журнале Chromium — `handshake failed …
net_error -100`), когда туннель принимает соединение, а сервер его не пропускает.
`nm-vless test` показывает, какие сайты доступны через сервер и из какой страны выходит
трафик, не подключая VPN:

```sh
nm-vless test "Мой сервер" https://mail.google.com/ https://claude.ai/
```

Если сайты не открываются и там, их блокирует сервер или его хостинг: выберите другой
сервер. Если в `nm-vless test` всё работает, а с подключённым VPN нет, включите запись
каждого неудачного соединения xray и повторите:

```sh
sudo nmcli general logging domains DEFAULT,VPN_PLUGIN:DEBUG   # затем переподключите VPN
journalctl -b -t nm-vless-service -f
sudo nmcli general logging domains DEFAULT                    # вернуть как было
```

Отладочный журнал содержит адреса, к которым вы подключались; не публикуйте его.

### Подключение долго открывается в Настройках

В версиях до 0.4.0 не было помощника аутентификации, и агент секретов GNOME Shell
заставлял каждый запрос ждать 25 секунд. Обновите пакет и перезапустите Настройки.

### Часть приложений идёт мимо VPN

`nm-vless check` находит две обычные причины после перехода с другого клиента:

- **Туннель другого клиента маршрутизирует половину адресов** (`0.0.0.0/1`, как
  `def1` в OpenVPN) с лучшей метрикой. Обычный маршрут по умолчанию другого клиента
  больше не мешает. Отключите или закройте другой клиент.
- **Системный прокси указывает на локальный прокси другого клиента** (например,
  `127.0.0.1:10809`), а `nm-vless-proxy-guard.service` не запущен. Браузеры,
  Electron- и GNOME-приложения идут в этот прокси напрямую. Запустите его
  (`systemctl --user enable --now nm-vless-proxy-guard.service`; после следующего входа
  в систему он запускается сам) или выключите прокси в **Настройки → Сеть → Прокси**.
  Уже запущенные приложения могут продолжать использовать старый прокси (например,
  Claude Desktop передаёт его своим дочерним процессам как `HTTPS_PROXY`),
  поэтому один раз перезапустите их.
- **`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY` указывают на локальный прокси** в
  окружении. Консольные программы идут через него и перестают работать, когда он
  пропадает. Уберите эти переменные там, где они заданы, и перезапустите программы.
- **DNS-запросы уходят мимо туннеля** у подключений, созданных до 0.4.0.
  `nm-vless check` выводит команду `nmcli`, которая исправляет каждое из них;
  подключения из подписок исправит и ближайший `nm-vless subscription update`.

Расшифровку типичных ошибок см. в разделе Troubleshooting [README.md](README.md#troubleshooting).

## Ограничения

- Только VLESS; ссылки VMess, Trojan, Shadowsocks, Hysteria2 в подписках пропускаются.
- Весь трафик идёт в туннель; раздельной маршрутизации пока нет.
- `allowInsecure` (TLS без проверки сертификата) намеренно не поддерживается.
- Зашифрованные ссылки провайдеров вида `happ://crypt…` закрыты и не читаются.
- Редактору нужен GTK 4 (Настройки GNOME); старый `nm-connection-editor` на GTK 3
  может включать VLESS-подключения, но не редактировать их.
